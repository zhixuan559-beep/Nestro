## 第十一项：专家模板

目标：提供可复用的专家角色模板，帮助用户快速创建专家，同时不覆盖或破坏现有专家配置。

### 功能范围
- [x] 内置专家模板目录，覆盖研究分析、商业经营、产品研发、内容创作、教育成长、项目管理和风险控制等场景。
- [x] 自定义模板保存：从当前专家配置生成模板；同名自定义模板更新，内置模板名称受保护。
- [x] 模板分类与搜索：支持按分类筛选，并搜索名称、说明和角色指令。
- [x] 使用模板：将模板配置载入专家编辑器，由用户确认后创建或更新专家。
- [x] 自定义模板删除；内置模板不可删除。
- [x] 模板 JSON 导入/导出，导入前预览；同名自定义模板更新，内置模板不可覆盖。
- [x] 模板数量、名称、指令长度、分类、描述和模型参数校验。
- [x] 自定义模板沿用本地持久化与现有备份/恢复链路。
- [ ] JVM 单元测试与 Android UI 回归测试通过。
- [ ] 构建/CI 验证通过后，才将第十一项标记为完成。

### 执行约束
- 模板只保存专家角色配置和提示词，不执行模板内代码。
- 模板应用不会自动授予技能、文件、无障碍或其他系统权限。
- 内置模板与用户自定义模板分开管理；用户数据不得被内置模板更新覆盖。
- 不改变第1项专家系统已有能力，不把第11项拆成新模块。


## 第十二项：双模型对比

目标：让用户用同一条任务指令同时调用两个已配置模型，直观比较回答质量；不修改当前聊天的活动模型，也不把一个模型失败后的请求偷偷切换到另一个模型。

### 功能范围
- [x] 从统一模型目录选择两个不同且当前可用的模型，校验服务商、模型启用状态和可用 API Key。
- [x] 支持不同服务商模型组合；密钥仅在请求时从加密仓库读取，不进入页面状态或比较记录。
- [x] 同一用户提示词和可选系统指令分别发送给两模型，两个请求并行执行，分别流式显示结果。
- [x] 两个请求独立处理失败；一侧失败时保留另一侧已生成内容，不将模型 A 的请求故障切换到模型 B。
- [x] 支持停止本次双模型请求、清空结果、复制任意一侧回答。
- [x] 宽屏并排展示，手机窄屏纵向展示；模型列表随可用模型目录更新。
- [x] 增加模型选择、重复选择、不可用模型、空提示词及长度上限等策略测试。
- [x] 静态源码、分支差异与结构复核完成；括号结构检查通过（不等同于 Kotlin 编译）。
- [ ] Kotlin 编译与 JVM 测试执行；模拟器/真机验收留待十九模块全部开发完成后统一执行。

### 执行约束
- 双模型比较只使用用户明确选择的两个模型；不得静默改用活动模型或其他备用模型。
- 两侧共享同一份用户输入和系统指令，但请求 ID、流式状态、错误和输出相互隔离。
- 停止操作必须取消两侧请求并释放网络连接；任何一侧失败都不能抹掉另一侧结果。
- 比较请求不写入普通聊天记录，不改变当前会话、活动模型或模型故障切换设置。
