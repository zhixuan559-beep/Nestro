# Nestro 品牌与移动端交互设计稿

版本：Draft 1  
设计范围：品牌标识、Android 手机端首页、主对话、专家协作、工具与工作流、记忆、Phone Agent、媒体创作、日历与设置。  
设计原则：轻量、清晰、可信；以一句话入口为中心，不把所有模块堆在首页；普通聊天与任务执行严格区分。

## 1. 品牌方向

- 产品名：Nestro（采用首字母大写的品牌字标，不使用全大写）。
- 品牌符号：连续折线构成的 N，表达模型、专家、工具之间的连接与调度。
- 主色：深海军蓝背景 + 青绿到蓝紫渐变符号。
- 辅色：浅雾白内容面、低饱和蓝紫强调色；成功/警告只用于状态，不做装饰。
- 字体：Android 系统无衬线字体；标题中等字重，正文常规字重，避免粗体堆叠。
- 图形语言：圆角卡片、细分割线、轻阴影；避免过度赛博光效、密集渐变和小字。

图标矢量草稿：`docs/design/nestro-mark.svg`。它是概念稿，应用图标安全区、Adaptive Icon 前景/背景和不同密度导出仍需在 Android 资源阶段处理。

## 2. 信息架构

底部主导航保持四个一级入口：

| 入口 | 职责 | 默认行为 |
|---|---|---|
| 首页 | 对话入口、最近任务、快捷模块 | 打开后不自动启动 Agent |
| 任务 | Agent、工作流、审批、执行状态 | 展示运行中/等待用户/已完成/失败 |
| 记忆 | 全局、项目、会话记忆 | 展示范围与来源，支持检索和管理 |
| 我的 | 模型/API、插件/MCP、权限、主题、备份 | 配置与系统管理 |

工具、专家团、日历、媒体编辑器、Phone Agent 等作为首页快捷入口或侧边抽屉二级页面，不额外挤占底部导航。

## 3. 核心页面

### A. 首页 / 对话入口

- 顶栏：Nestro 标识、当前项目切换、搜索/新建入口。
- 欢迎区：一句简短引导，不使用虚构机器人形象占据首屏。
- 主输入框：支持文字、语音、图片、文件；发送后先由主模型判断是普通回答还是明确任务。
- 快捷能力：专家团、工具、工作流、Phone Agent、媒体创作、日历。
- 最近任务：只显示真实任务状态与更新时间；普通聊天不混入任务执行列表。
- 普通聊天默认不调用设备操作、专家团或执行工具；只有任务模式或明确任务授权才进入执行链。

### B. 主对话

- 消息区：用户与模型消息清晰区分，长内容可折叠。
- 输入区：文本、语音、附件、多模态内容统一入口。
- 任务切换：普通对话 / 任务执行两种模式，状态可见。
- 任务开始前展示目标、计划和需要的权限；执行中显示当前步骤、工具、审批点和暂停原因。
- 高风险动作单独展示确认卡片；用户拒绝后停止该动作，不以默认拒绝替代授权弹窗。

### C. 专家团

- 顶部分类：推荐、技术、生活、创作、自定义。
- 专家卡片：名称、专长、能力说明、可用状态、进入详情。
- 团队工作区：主模型、专家成员、任务分工、依赖关系、并发进度、汇总结果。
- 两种模式：用户手动选择专家；或用户明确创建项目后由主模型组织专家团队。

### D. 工具与插件

- 分类：效率、创作、生活服务、开发、媒体。
- 每个工具展示用途、输入输出、所需权限、来源与版本。
- 插件/MCP/工作流统一审批入口；首次授权、单次授权、持续授权和撤销状态明确区分。
- 不把 API Key 明文显示在列表或日志中。

### E. 任务与工作流

- 状态筛选：进行中、待审批、等待用户、已完成、失败。
- 任务详情：目标、计划、当前步骤、执行日志、产物、恢复点。
- 审批弹层：显示工具、动作内容、数据范围和授权期限；按钮为“本次允许”“持续允许”“拒绝”。
- 恢复入口只在可恢复状态出现；不把“已排队”显示为“执行成功”。

### F. 记忆

- 范围切换：全局、项目、会话。
- 每条记忆展示内容、来源、更新时间、共享范围。
- 共享项目记忆必须展示来源项目与授权状态。
- 提供搜索、编辑、删除、导入/导出。
- 召回结果不等于永久记忆；在对话上下文中标注来源，避免把旧消息当作当前指令。

### G. Phone Agent

- 展示虚拟屏连接状态、当前任务、操作授权、任务日志。
- 支持暂停、继续、停止、交还用户、恢复虚拟屏。
- 导航场景先打开路线预览；显示起点、终点、交通方式和地图页面实际返回的路线信息。
- 用户确认路线后才交接到真实主屏；真实导航由用户本人启动。

### H. 媒体创作

- 项目列表与素材库入口。
- 编辑器以预览区为主，时间线和属性面板为辅。
- 当前已实现轨道能力以代码实际支持为准，不在设计稿中假设多轨、关键帧或转场已经上线。
- 渲染任务显示队列、进度、取消/恢复状态和输出文件。

### I. 日历

- 月/周/日视图与今日安排。
- 自动化日程与普通日历事件明确区分。
- 自动化执行显示触发时间、任务状态和最近执行结果。

### J. 我的 / 设置

- 模型与 API：供应商、模型、连接测试、默认模型、故障切换。
- 插件与 MCP：连接、授权、权限范围。
- 隐私与安全：设备权限、持续授权、数据备份。
- 外观：浅色/深色/跟随系统。
- 关于 Nestro：版本、更新、许可证。

## 4. 关键交互规则

1. 用户一句话进入主模型；普通聊天只回答，不默认启动工具或 Agent。
2. 任务执行必须先明确目标与完成标准，再进行调度。
3. 专家团、Agent、插件、MCP、工作流由统一任务协调层调度，状态与审批统一呈现。
4. 创作任务允许组合执行型能力，例如搜索/下载素材后回到媒体编辑器继续创作。
5. 高风险操作必须停在可理解的确认点；用户接管后保留任务上下文和恢复点。
6. 所有“完成”状态必须来自实际执行结果，不允许用计划或模型口头声明代替。

## 5. 当前实现映射与落地边界

- 现有 Compose 主入口为 `NestroApp.kt`，已有首页、聊天、专家、团队、技能、模型、协作工作台、媒体编辑器、工作流等路由/页面入口。
- 本稿是视觉与信息架构设计，不代表这些页面已经全部按稿实现。
- 下一步 UI 落地应复用现有页面和组件，先做导航、间距、字体、卡片和状态呈现统一；不另起一套重复页面，不删除既有功能。
- 最终验收需在真实 Android 构建与设备尺寸下检查：小屏适配、键盘遮挡、长文本、横屏/分屏、深浅主题、无障碍字号。
