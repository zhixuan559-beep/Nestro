# Nost 移动端交互设计规范

版本：Draft 3（聊天优先极简版，UI 初步落地）

## 1. 产品原则

- 产品展示名称：**Nost**。仓库名、Kotlin package、内部数据库键等技术标识暂不随品牌名改动。
- 免注册：安装后直接进入聊天。不存在 Nost 账号注册、登录、手机号验证、账号找回或强制云端账号体系。
- 本地优先：会话、专家、专家团、Skill、工作流及个人配置默认保存在设备本地。
- 模型供应商 API Key / OAuth 是用户连接第三方模型服务，不是 Nost 账号。保留现有供应商连接能力。
- 唯一主入口是聊天。用户通过自然语言提出需求，由主模型判断是否需要工具、专家、工作流、MCP、Phone Agent 或日历能力。
- Agent、日历和执行器属于统一调度层，不作为用户必须手动进入的一级功能页面。

## 2. 视觉系统

- 默认外观：GPT 风格的极简黑白界面。
- 浅色：白色背景、黑色正文、浅灰分隔线。
- 深色：黑色背景、白色正文、低对比灰色分隔线。
- 不使用霓虹渐变、玻璃拟态、大面积彩色卡片、装饰性光效或复杂背景。
- 默认只使用系统图标、清晰文字、留白和必要的状态提示。
- 主题、强调色、字体大小等个性化选项由用户在设置中控制；不将品牌色强加给用户。
- 品牌符号沿用用户提供宣传图中的蓝紫渐变双环无限符号；只将字标替换为 Nost。禁止重新绘制成字母 N 或另造符号。现有 SVG 概念稿尚未完成像素级还原，不得作为最终 Logo 验收。

## 3. 主界面

- App 启动直接进入聊天主页，不显示欢迎流程、账号注册或登录。
- 顶栏只保留菜单/侧栏入口、当前会话或项目上下文，以及必要的模型状态。
- 聊天消息区域采用简洁气泡/文本排版。
- 底部输入区统一承载文本、语音、图片和文件输入。
- 输入框附近提供轻量工具入口，不把所有能力做成首页卡片。
- 普通聊天不自动调用工具；主模型先判定意图，符合任务条件时再进入统一调度。

## 4. 侧栏与专家目录

侧栏用于浏览和切换，不构成第二套工作台：

- 最近对话与历史会话。
- 项目/工作区。
- **专家与专家团共用一个目录**，目录内分为“专家”和“专家团”两个分组。
- 单个专家可直接打开独立聊天。
- 专家团可由已有专家组合创建，打开后进入群聊式协作会话。
- 一个专家可加入多个专家团；各群成员关系相互独立。
- 删除专家时，需明确处理其所在专家团成员关系；移出某个群不得删除专家本身。
- 删除专家团不删除其成员专家；解散群组与删除群聊数据应提供明确确认。
- 群聊记录与普通会话一样可检索、重命名和删除。

## 5. 工具与设置目录

工作流、Skill、插件、MCP、模型服务、API 配置、权限、知识库、记忆、产物库及专用创作工作区统一放在“工具与扩展”目录或设置中。目录采用简洁列表与分类，不创建重复的一级工作台。外观设置提供跟随系统、纯白、纯黑三种模式。

建议分组：
- 模型与服务：供应商、模型、API Key、OAuth 连接、默认模型与故障切换。
- 工具与插件：内置工具、第三方插件、MCP 连接及权限。
- 工作流与技能：Skill、工作流定义、导入导出与启停。
- 个性化：浅色/深色/跟随系统、强调色、字体与字号。
- 数据与隐私：本地备份、数据管理、应用权限。

## 6. 隐藏式辅助能力与统一调度

- Phone Agent 不在主导航或侧栏中提供独立“手动操作中心”。由主模型根据对话目标判断是否需要调用；涉及设备权限、敏感动作或主屏接管时仍走既有审批与用户确认链路。
- 日历不作为独立一级页面。由对话、任务或工作流按需调用；需要查看/编辑具体日程时，通过对话返回上下文相关入口。
- 媒体创作、文件处理、网页搜索等能力由统一调度器按任务需要调用；必要时可在对话中展示专用工作区或结果页，但不能迫使用户先选工具。
- 用户只向对话入口表达目标；主模型负责意图识别、计划、工具分配、专家协作、审批、执行、恢复与结果汇总。

## 7. 页面边界

允许存在的辅助页面（仅从上下文或目录进入）：
- 专家/专家团目录与聊天。
- 工具与插件目录。
- 模型/API 设置。
- 工作流/Skill 编辑器。
- 项目、会话历史、记忆和本地数据管理。
- 由任务上下文打开的媒体编辑器、文件预览等专用工作区。

不得作为侧栏或一级导航入口：
- Phone Agent 控制台。
- 日历工作台。
- Agent 管理/执行中心。
- 注册、登录、账号中心。

## 8. 实施约束与验收

- 优先复用现有 Compose 页面、专家数据模型、团队数据模型、聊天持久化、审批、任务协调器与调度服务；禁止重复开发第二套聊天/团队/任务系统。
- 调整 UI 导航时，不删除 Phone Agent、日历、工作流、专家协作等底层能力，只移除违背统一调度原则的独立入口。
- 账号移除范围仅指 Nost 自身账号体系；第三方模型供应商 OAuth/API 连接必须保留。
- 任何需要同步、备份或跨设备的能力必须明确其实际数据边界，不得暗中引入强制账号。
- 本设计文档不等于 Compose 界面已全部完成。后续需逐项核对现有路由入口、实际页面、调用链及测试，再修改导航。
- 按既定开发顺序：完成代码审计和必要补齐后，最后统一进行云端编译、测试和 APK 构建；本轮不提前触发 CI 或构建。



## 9. 当前代码落地记录（未编译验收）

已在 UI 代码中初步落地：
- 默认视觉改为黑白极简，用户可选择跟随系统、纯白或纯黑。
- 主聊天空状态去掉装饰性图形和功能推荐卡片。
- 顶栏移除“双模型 / AI 共建”常驻入口，改为工具与设置入口。
- 侧栏收敛为对话、项目、专家与专家团、工具与扩展、设置。
- 专家和专家团共用一个目录入口，通过目录内切换查看。
- 日历与 Phone Agent 不再作为侧栏入口或常规页面路由；底层日历调度和 Phone Agent 执行模块保留。
- 工具与扩展目录统一承载模型、Skills、工作流、插件、MCP、知识库、记忆和其他辅助工作区。

仍需后续核查：
- 专家团独立聊天会话与成员关系生命周期是否完整，尤其是群聊记录、解散与删除的区别。
- 全部二级页面是否遵循黑白主题，而非仅主聊天、知识库和导航区域。
- Launcher 图标是否完成原图双环 Logo 的像素级还原与资源集成。
- 最终编译、测试和设备验收尚未执行。
